# Технологический стек

Первая версия Library Component Editor предназначена для моделирования инженерного оборудования в **Renga Professional 9.4.34553** под Windows x64. Целевые версии — **Renga API 2.51**, **STDL 4.4** и **Lua 5.4.6**. [Выпуск Renga](https://help.rengabim.com/ru/Content/release_notes_online.html) · [Версии API](https://help.rengabim.com/api/_changelog.html) · [Версии STDL](https://help.rengabim.com/stdl/ru/changelog.html) · [Язык STDL](https://help.rengabim.com/stdl/ru/)

## Дерево построений и Lua

Исходники компонента — Lua с операциями построения и JSON с определениями параметров и портов. При открытии редактор восстанавливает дерево по исходникам. При правке через дерево он обновляет соответствующий фрагмент Lua, сохраняя формулы, комментарии и остальной пользовательский код.

Например, пользователь вычитает цилиндр из корпуса. В дереве появляется операция «Вычитание» со ссылками на оба тела, а в Lua — вызов `Subtract(body, cutter)`. Если вручную заменить радиус цилиндра с `10` на `diameter / 2`, дерево должно показать формулу и связь с параметром, а 3D-вид — перестроить отверстие. При построении стиля в Renga вычитание выполняет сама Renga. [Операции с телами в STDL](https://help.rengabim.com/stdl/ru/group___three-dimensional.html)

Для прототипа предлагаем сохранять функции и циклы, которые редактор пока не умеет представить построениями, в узле «Фрагмент Lua». Если от фрагмента зависит форма, 3D-вид помечается как неполный. При синтаксической ошибке введённый текст сохраняется, а редактор указывает строку ошибки и показывает последний корректный результат с соответствующей пометкой. Вопрос об исполнении произвольного Lua в локальном предпросмотре остаётся открытым.

## Вычитание в локальном 3D-виде

**Manifold (Apache-2.0) — кандидат для прототипа.** Планируем вычислять вычитание на треугольных сетках через C-интерфейс Manifold и передавать результат в HelixToolkit.Wpf. Цель — показывать изменение выреза сразу при перемещении режущего тела. Open CASCADE Technology остаётся резервным вариантом на случай выявленных ограничений сеточного построения. [Manifold](https://github.com/elalish/manifold)

Примем решение по Manifold после проверки на Windows x64 в Renga 9.4.34553.

1. Загрузить плагин с библиотекой Manifold. Вычесть повёрнутую призму из корпуса и переместить её в редакторе. Вырез должен следовать за призмой.
2. Изменить размер призмы формулой в Lua. Затем изменить её положение через дерево, сохранить и открыть исходники заново. Проверить формулу, комментарии и положение обоих тел.
3. Собрать `.rst`, импортировать категорию в Renga и сравнить форму, размеры и положение выреза с локальным предпросмотром на двух типоразмерах. [Проверка шаблона в Renga](https://help.rengabim.com/stdl/ru/testing_and_debugging.html)

## Требования к рабочему месту

| Сценарий | Что требуется |
| --- | --- |
| Создание компонента, ручная правка Lua, локальный предпросмотр и сохранение исходников | Windows 10 или 11 x64, Renga Professional 9.4.34553, плагин и среда выполнения .NET Framework 4.8 или 4.8.1. Открытые библиотеки редактора планируется поставлять с плагином. |
| Сборка `.rst` или команда «Проверить в Renga» для изменённых исходников | Дополнительно требуется папка `RstBuilder` из официального Renga STDL SDK с поддержкой STDL 4.4. В ней вместе находятся `RstBuilder.exe` и `StyleTemplate.dll`. Сборщику нужны библиотеки Microsoft Visual C++ Redistributable x64. |
| Импорт уже собранного `.rst` | Достаточно Renga Professional. Категория импортируется штатными средствами. |

При первой сборке пользователь выбирает путь к `RstBuilder.exe`, и редактор запоминает его для следующих запусков. Комплект STDL пользователь скачивает у Renga Software. При подготовке дистрибутива учитываем ограничения на передачу SDK и его частей по п. 3.5.6 лицензионного соглашения Renga. [Скачать Renga STDL SDK](https://rengabim.com/stdlsdk/) · [Лицензионное соглашение Renga](https://rengabim.com/files/eula_ru-ru.pdf)
